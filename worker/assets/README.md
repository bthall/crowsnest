# Crowsnest brand assets

`crowsnest-mark.png` is the transparent crow emblem used in the dashboard header, empty state, and browser favicon. The interface uses charcoal/slate, warm ivory, and copper-gold, with separate green/amber/red status colors.

The source image was generated with the built-in image-generation tool, then refined with the same tool. The PNG is included in the tracked project and embedded in the Worker build; the dashboard does not depend on a remote image host.

## Generation prompt

Use case: logo-brand. Create a production-ready standalone logo emblem for Crowsnest, a private Docker fleet monitoring dashboard. Subject: a striking, intelligent crow with a hooked beak and a folded angular wing, subtly forming an open C silhouette and evoking a ship's lookout. Style: bold flat graphic mark, precise clean edges, confident contemporary nautical identity, instantly legible at small sizes. Palette: warm ivory for the main crow and a restrained copper-gold eye/accent, designed for a charcoal/navy dashboard. Composition: one centered emblem, square canvas, symbol fills about 80 percent of the image with balanced breathing room. Background: genuinely transparent. No text or lettering, no mockup, no scenery, no gradients, no shadows, no border, no extra badges, no tiny feather details, no watermark.

## Refinement prompt

Use case: logo-brand, refine this Crowsnest emblem. Preserve the overall ivory/copper/dark-slate palette, centered composition, folded wing, open C silhouette, and transparent background. Make the bird clearly a crow rather than an eagle: change its hooked eagle beak to a long, fairly straight, sharply pointed corvid beak, with a smooth crow head profile. Clean the silhouette to crisp flat edges with no mottled or stray pixels around the bird. Keep the wing bold and the copper eye accent. No text, no background, no gradients or texture. Deliver the final standalone transparent logo mark.

## Compatibility

The Crowsnest name changes the product identity. Installed collector filenames, project/container names, installation paths, reporting endpoints, and host credentials remain compatible.
